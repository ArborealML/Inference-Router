# Use AIR from Pi CLM

With Pi 1.3 and an existing Pi CLM installation, install the extension beside the launcher. The installer recognizes the launcher that ships an `air_provider.py` helper. It checks the launcher layout before replacing files. For upgrades, run the same installer and use `/reload` in the open session. The installer embeds the catalog helper in the extension entry so the running Pi process picks up both together.

```sh
python3 tools/pi-air/install.py /path/to/pi-clm.py
AIR_CONFIG=/path/to/router.toml pi-clm
```

The launcher reads the local AIR listener from the configuration. Set `AIR_API_KEY` when that listener requires authentication. The existing legacy backend discovery still runs when the launcher has no AIR configuration. Existing Pi flags, session directory, tools and CLM extensions are available in both modes.

- **Select a model** with Pi’s built-in `/model`. Both loaded and cold configured models appear. A fresh session prefers a healthy resident. If none is resident it starts on the configured default when available. Pi restores its saved model on resume. Catalog and engine notifications update the picker while the session is open. Reconnection and `/reload` fetch the current snapshot.
- **Read throughput** in the AIR footer. Pi shows Reading Context, Reasoning, Responding, Preparing Tool, or Executing Tool as those events arrive. A local model switch reports its four completed milestones in 25% increments: engine checks, peer release, target launch, and readiness. The switch percentage counts steps, not elapsed load time. Reading Context shows prompt completion, for example `Reading Context (47.5%)`. Prompt completion includes cached tokens; throughput measures newly processed tokens. During prefill, Maya and Strata can report newly processed tokens and elapsed prompt time. During decode, Pi uses per-token timings or streaming usage counts where available. A tilde marks a text-based estimate (four characters per token). A dash means no usable sample has arrived; a backend without prompt-progress events cannot show live prefill. For a model shared by different backend families, AIR selects the engine after admission. Pi omits family-specific request flags and uses the progress or timings the stream supplies. Final backend timings replace estimates. Use `/air-status` for the ticket ID.
- **Inspect context** with `/context`. The picker labels each configured profile with its capacity and slot count by engine, alongside observed residency. Use `/context NAME` to choose a profile or `/context default` to use the configured default. RPC clients can send these commands through `prompt`. Choices follow the current session branch and model.
- **Change the next turn** with `/model` or `/context`. In an AIR turn, tool continuations and retries use the captured AIR model and profile. A queued follow-up uses the selection in effect when Pi starts it. Selecting and queueing are local operations. AIR performs any necessary backend switch during request admission.
- **Fit the transcript** before downsizing. At dispatch Pi estimates the prepared transcript and reduces the output cap to the remaining room. This also applies to native summaries and CLM compaction. A prompt that fills the window still requires a larger profile or a shorter input. When multiple engines advertise a profile name, Pi budgets to the smallest advertised capacity for that name. If the catalog supplies no single default profile, Pi shows a warning and lets AIR choose the tier using the captured context minimum. A withdrawn selection requires a new choice.
- **Follow a request** in the Pi footer or with `/air-status`. The extension reads the ticket returned by the original inference response. While the displayed ticket is queued, the composer shows **Waiting**. Dispatch restores Pi’s usual working indicator. The footer clears when the stream ends. Pi shows the result in the transcript, and the command can read the latest ticket on this branch after completion. `/air-cancel` aborts this session’s active inference connection. If several calls overlap on one branch, run `/air-cancel` to list their IDs and use `/air-cancel ID` for the intended call. Pi’s ordinary abort also propagates to AIR.

Live Pi qualification verified 32k and 256k inference. With two requests in flight, cancelling the selected ticket left the other request running through completion.

The extension uses read-only admin discovery and ticket snapshots. Pi streams the original response through its OpenAI adapter. AIR launcher settings disable automatic transport and agent-error retries. The client sends its session ID as `X-Inference-Thread`, the chosen capacity as `X-Inference-Required-Context`, and `X-Inference-Preferred-Profile` for cold launches. A free lane with the required context can serve the request on a larger resident profile. AIR tickets carry the optional Pi session title and tmux session name.

Run the catalog checks with `node --test tools/pi-air/catalog.test.mjs`. With Pi 1.3 on the path, `python3 tools/pi-air/test_prompt_budget.py` verifies a same-session extension upgrade and that a new prompt exceeding the selected window reaches the user as an error before an inference or automatic compaction request reaches the loopback fixture.

`python3 tools/pi-air/test_turn_selection.py` checks the request model and profile during a held tool call, retry, queued follow-up, and cancellation. It also checks child-session attribution, direct registry calls with the caller's thread and cancellation, threshold and retention settings for automatic compaction, and separate routing for manual and automatic summaries.

AIR registers a default output limit of 65,536 tokens for DeepSeek and 32,768 for other models. The full allowance applies at 65,536 context for other models and 98,304 for DeepSeek. Smaller profiles keep input room, allowing at least a quarter-window for output. An explicit smaller request limit is honored.
